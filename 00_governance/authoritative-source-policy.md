# Authoritative Source Policy

## Purpose
Prevent conflicting project state across GitHub, Google Drive, chat threads, exported artifacts, and agent work products.

## Authority hierarchy
1. Explicit Human Owner decisions.
2. Accepted artifacts committed to `main` in `efong505/ekewaka-publishing`.
3. Governing master prompt and current PM handoffs where not superseded by accepted repository state.
4. Working drafts and research artifacts.

## Rules
- `main` is the authoritative project branch.
- Critical decisions must be recorded in the decision register.
- A draft, chat response, exported document, or external copy does not supersede accepted repository state unless explicitly adopted.
- Current laws, prices, fees, platform terms, tax rules, ISBN rules, distribution terms, and vendor capabilities must be reverified when used for a material decision.
- Research artifacts must distinguish verified current facts, historical facts, secondary commentary, working assumptions, estimates, uncertainty, and professional-review items.
- Independent verification is required for high-impact legal-research, financial, contract-framework, package, architecture, and launch artifacts.
- No agent may self-approve a reserved Human Owner decision gate.
